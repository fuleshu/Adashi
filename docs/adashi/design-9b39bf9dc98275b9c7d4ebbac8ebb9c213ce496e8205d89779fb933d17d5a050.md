## Defects corrected during acceptance

- Memory retrieval still called an initialization helper. Initialization now owns
  that work; read-only snapshots never insert memory rows.
- Editors previously retained text but adopted a refreshed resource version. A
  stale draft could therefore silently overwrite another writer. Text fields,
  Markdown editors and completion forms now retain the version of their original
  content, preserve the draft on rejection, and offer explicit current-value
  reload. Clean editors still follow external changes.
- The new Markdown editor synchronization effect was moved to the component's
  hook level and exercised in the native application.
- Cached hidden diagram views no longer fit a zero-size viewport, avoiding an
  invalid SVG transform while another workspace view is active.

## Reproduction

From the repository root, build the frontend before the native desktop binary:

```powershell
npm run build
cargo build --manifest-path src-tauri/Cargo.toml --bins --offline
cargo test --manifest-path src-tauri/Cargo.toml --lib --offline
cargo test --manifest-path src-tauri/storage-api/Cargo.toml --offline
node scripts/check_versioned_draft.mjs
python -B scripts/check_read_only_storage.py --binary src-tauri/target/debug/adashi-mcp.exe
python -B scripts/check_storage_core.py --binary src-tauri/target/debug/adashi-mcp.exe
python -B scripts/check_storage_parity.py --binary src-tauri/target/debug/adashi-mcp.exe
python -B scripts/check_mcp_error_contract.py --binary src-tauri/target/debug/adashi-mcp.exe
node scripts/check_native_storage.mjs
cargo build --manifest-path src-tauri/Cargo.toml --no-default-features --bin adashi-mcp --offline
```

The native test requires Windows/WebView2 and Playwright. If Playwright is provided
by a separate development runtime, set `ADASHI_PLAYWRIGHT_PACKAGE` to its package
directory for that command. Each integration check uses a disposable project
under `target/`; no installed application or real project is upgraded by a test.

Text and server SQL storage remain intentionally unavailable until their later
implementation tasks. SQLite/WAL is the compatibility backend, not the proposed
Git-mergeable data format.
